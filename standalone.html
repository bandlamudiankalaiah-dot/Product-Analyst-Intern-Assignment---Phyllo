2. Task 1 – What Doesn't Match?

Comparison of documented API contracts against captured responses

Most Serious Issue
Finding B – Monetary format mismatch

The monetary-format mismatch is the most serious because it directly affects financial calculations and reporting.

Finding Documentation Actual Impact
Finding A – Status mismatch Documentation says status can be: pending, shipped, delivered, cancelled.
orders_page1.json → ord_1003 → status = refunded
 Clients may mishandle or reject refunded orders.
Finding B – Monetary format mismatch
(Most serious issue) 		Documentation says all monetary amounts are integers in the smallest currency unit.
orders_page2.json → ord_1006: subtotal = 44.0 tax = 3.63 shipping = 5.99 total = 53.62
 This can cause incorrect financial calculations because the API format differs from the documented contract.
Finding C – Customer email mismatch Documentation says customer email is always present.
orders_page2.json → ord_1005 → email = null
 Clients assuming email is always present may fail or behave incorrectly.
Finding D – Pagination mismatch Pagination indicators indicate whether remaining records exist.
orders_page1.json reports: has_more = false next_cursor = cur_8f2a19bd But orders_page2.json exists using that cursor.
 A client relying on has_more may stop after page 1 and miss orders.
Finding E – Missing-order response mismatch Documentation says GET /v1/orders/{id} returns HTTP 404 if the order does not exist.
order_ord_9999.json returns HTTP 200 with: order = null
 Clients may incorrectly treat a missing order as a successful response.

5. Task 3B – Bug Report

Factual engineering bug report with problem, expected, impact, and fix

Title:
API returns monetary amounts in decimal dollars instead of documented smallest currency units
Problem:
GET /v1/orders?starting_after=cur_8f2a19bd returns ord_1006 with: subtotal = 44.0 tax = 3.63 shipping = 5.99 total = 53.62
Expected:
Monetary fields should consistently be integers representing the smallest currency unit according to the API documentation.

For example:
If the intended amount is $53.62, the documented representation would be 5362.
Impact:
Clients may interpret the values incorrectly, resulting in inaccurate revenue calculations and financial reporting.
Suggested fix:
Return monetary fields consistently using integer smallest-unit values, or formally update the API contract and consumers if decimal currency values are intended.
